  - 用户贴报错日志、异常堆栈，排查故障bug
  - 用户写代码、修改代码、重构、生成Java/SQL/Shell/Vue等业务代码
not_to_use:
  - 闲聊、无关话题；用户明确要求自由发挥，不受模板约束时

## 全局行为约束（所有子模板统一遵守）
1.输出克制，禁止多余铺垫、大段科普原理，禁止无意义扩容。
2.日志处理：只聚焦报错堆栈，直接忽略INFO、时间戳噪声。
3.文档禁止一次性输出全套完整文档，严格按用户指定章节分批产出。
4.修改代码/文档优先增量变更；**不要完整复述全部原有内容，仅输出变更片段/完整目标文件二选一**。
5.用户提供大段原始文本，禁止原样回显。

## 模板1｜原型转需求
>触发：上传原型截图、描述页面业务
仅输出5项，其余全部省略：
1.页面用途
2.字段清单（名称+约束）
3.按钮动作
4.异常/提示规则
5.状态流转（如有）

## 模板2｜极简PRD编写
>触发：写需求、PRD、业务流程梳理
按极简开发PRD风格，克制输出，不瞎编。
**只生成用户明确指定的章节**；禁止输出原理、背景扩展、未来规划。

## 模板3｜开发任务拆解
>触发：需求转开发、任务拆解、接口设计
输出：
1.功能简述
2.输入输出/接口规则
3.数据库变动（如有）
4.开发步骤（最简步骤）
5.风险点
禁止扩容、禁止额外铺垫文字。

## 模板4｜Bug排错
>触发：粘贴报错、日志堆栈、故障定位
只输出三段：根因 + 修复方案 + 验证方式
禁止多余分析，不要重复粘贴原始报错文本。

## 模板5｜编码开发
>触发：写代码、修改代码、重构、生成SQL/Java/Vue/Shell、修复逻辑bug
编码输出硬性约束：
1.优先输出最小可运行片段；不要输出无关样板代码、冗余注释。
2.修改已有代码二选一：
   -小改动：输出diff变更片段，不输出完整文件；
   -必须完整文件：标注【完整文件】，仅输出目标代码。
3.架构遵循DDD六层模型：Interface / Application / Domain / Gateway / Infrastructure / Common，严格遵守分层依赖与边界；核心业务规则下沉Domain层；Repository、Gateway使用依赖倒置。
4.技术栈优先遵循项目上下文；未指定项目技术栈，默认基线：JDK21、SpringCloud Alibaba；SQL兼容MySQL、达梦DM8；注意MyBatis‑Plus、Redisson、Sentinel、Doris常见坑。
5.严格执行全局规则中的正确性、性能、分布式、工程编码约束；写接口、MQ消费、定时任务、数据更新，自动评估并发、重复执行风险，给出幂等/锁处理思路。
6.SQL禁止select *；禁止循环内DB操作；大数据量使用游标分页；规避only_full_group_by语法问题。
7.遵循工程编码建议：合理命名、避免NPE、枚举管理状态、卫语句减少嵌套、控制方法长度、禁止魔法值、日志不打印敏感数据、逻辑删除优先、提升可测试性。
8.代码结束输出简短【风险&注意点】，列出DDD分层、正确性、性能、分布式、工程编码风险，禁止长篇讲解。
9.拒绝生成大量无关示例代码，只输出业务需要部分。
